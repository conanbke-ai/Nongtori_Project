- 개발명: **농토리 (Nongtori)**
- 새 기준 저장소: `conanbke-ai/Nongtori_Project`
- 프로젝트 목적: 취업용 포트폴리오 중심의 스마트팜/농업 현장 지원 서비스
- 딸기는 첫 적용 작물로 유지하되 서비스 구조는 딸기 전용으로 고정하지 않음

### 기존 프로젝트에서 확인된 방향

- 딸기 생육/품질 등급 분류
- 숙도 분류
- 수해/병해충 분류·판별
- 응애 예찰
- 흰가루병 대응
- RGB + 열화상/IR 데이터 활용 검토
- 관수 전/후 비교 데이터 확보
- 농가별/환경별 데이터 차이 고려
- 고령 농민과 외국인 작업자를 고려한 UI
- 정찰 토끼 마스코트 및 농장 분석 대시보드 콘셉트

### 디자인 산출물

파일 라이브러리에서 다음 디자인 자산이 확인되었습니다.

- 파스텔 토끼 AI 분석 대시보드
- 파란 고글 토끼 마스코트 가이드
- 정찰 토끼 캐릭터 시트
- 귀여운 토끼 농장 순찰 스티커 시트

현재 GitHub 커넥터는 로컬/라이브러리의 바이너리 이미지 파일을 그대로 업로드하는 파일 파라미터를 제공하지 않아, 이 마이그레이션 커밋에서는 이미지 원본 자체 대신 `docs/DESIGN_GUIDE.md`에 해당 자산의 디자인 규칙을 보존합니다. 이후 이미지 파일을 저장소에 직접 추가할 수 있는 경로가 확보되면 `assets/design/`에 원본을 보존합니다.

### 코드 기준본 상태

연결된 GitHub 저장소, 대화 파일, 파일 라이브러리를 검색했으나 기존 딸기 프로젝트의 최신 실행 코드 기준본은 확인되지 않았습니다.

따라서 존재하지 않는 소스를 임의로 재현해 '이관 완료 코드'로 표시하지 않습니다. 앞으로 신규 구현은 `Nongtori_Project`에서 시작하고, 추후 기존 코드가 발견되면 기능 단위로 검증 후 점진적으로 편입합니다.

### 새 개발 표준

- Controller/API → Service → Domain → Repository Port → Infrastructure
- Strategy / Adapter / Repository / Factory 우선 검토
- 동일 조건문 3곳 이상 → Strategy 검토
- 동일 DB Query 2곳 이상 → Repository 검토
- Service 300~500 lines 초과 → 책임 분리
- 1 기능 / 1 목적 / 1 커밋
- local → simulation → staging → field/production

### 앞으로의 기준

이 문서 작성 시점부터 농업 프로젝트 관련 개발·리팩토링·테스트·문서 작업은 `Nongtori_Project`를 기준 저장소로 사용합니다.
